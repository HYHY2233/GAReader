# 四视图版本升级、修订与回退

本轮只升级并写入 `test-runs/four-views/` 中的隔离副本。正式 `var/` 和此前运行目录未迁移；GitHub 未推送。应用正式升级需要用户确认。

## 正式升级步骤

1. 正常停止旧网站，记录实际数据目录。保留旧程序目录和版本。
2. 在旧程序目录运行 `backup.cmd --data-dir "D:\论文库数据"`。保留生成 ZIP；不要只复制正在运行的 SQLite 数据库。
3. 将新版源码放入另一个本地非同步目录。用 Python 3.12 执行 `setup.cmd --data-dir "D:\论文库数据"`。setup 在已有库上先备份，再执行迁移、建立缺少的不可变快照和收集本地静态资源。首次取得新依赖需要联网；日常启动不安装依赖。
4. 执行 `.venv\Scripts\python.exe launcher.py check --data-dir "D:\论文库数据"`，随后 `start.cmd --data-dir "D:\论文库数据" --port 8000`。核对账户、评分、旧评论、两篇论文、四视图和新增批注后再投入使用。

所有维护和启动命令必须指定同一个实际数据目录。示例路径是占位符，不代表已创建该目录。旧数据没有可靠 PDF 对齐时保留明确降级；请不要手工修改已经发布的 `revisions/` 文件。

## 修改译文或替换来源

当前没有新增在线版本编辑器。停机后使用明确的维护命令：

```powershell
.venv\Scripts\python.exe launcher.py revise --data-dir "D:\论文库数据" --paper "论文UUID" --html "D:\修正稿.html" --mapping "D:\对应段落地图.json"
```

新 HTML 仍须通过完整标准双语格式与保真校验。校验失败不修改正式内容；通过后先备份，再生成快照并切换当前引用。没有实际内容变化时复用原修订。需要新 PDF 时加 `--pdf "D:\新原文.pdf"`；不指定时沿用当前快照 PDF，明确移除时使用 `--without-pdf`。不要同时指定二者。

**不指定 `--mapping` 会不带入旧地图**，避免把旧段落关系套在修正稿上。仍可从已校验 HTML 和实际 PDF 重新建立自动映射。地图或来源变化可能产生新修订。程序不会重写旧批注，无法安全投影的讨论标为旧修订，并提供旧快照入口。下载附件指向正在阅读的修订。

## 一致备份与恢复

停机后运行：

```powershell
backup.cmd --data-dir "D:\论文库数据" --output "E:\论文库备份"
restore.cmd --archive "E:\论文库备份\备份文件.zip" --target "D:\论文库恢复演练"
start.cmd --data-dir "D:\论文库恢复演练" --port 8001
```

备份包含数据库、所有论文快照、原 PDF、图像、映射及定位索引，附 SHA-256 清单。恢复校验 SQLite、外键、内容哈希、当前修订关系和锚点关系；仅允许新目录，不覆盖已有库。恢复会重新生成服务器密钥并清除旧会话，注册账户密码保留，匿名身份浏览器记忆不能继续由旧签名恢复。备份含账户密码哈希，保存在本机测试目录的演练备份不得公开上传。

## 回退

应用旧程序时，恢复**升级前备份到新目录**，再让旧程序明确指向该目录。不要把旧程序直接连到新版数据库，也不要反向删除迁移或手工删除新表。升级后产生的新批注不在升级前备份中；回退前另做一份新版完整备份以保留这些记录。保留新旧数据目录供核对，不混用、不覆盖。
