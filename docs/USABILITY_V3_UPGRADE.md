# 可用性修复 v3：启动、升级与回退

## 首次安装

解压完整源码到本地非同步目录，安装 Python 3.12，双击 `setup.cmd`，再双击 `start.cmd`。默认打开 `http://127.0.0.1:8000/`。首次安装联网下载锁定依赖，日常阅读不需要外部资源。源码包自带两篇标准译稿、原 PDF 和段落映射，不包含 Python 运行环境或任何用户数据。

注册、密码登录和记住上次身份的匿名登录保持不变。新上传要求至少一个分类和 1—5 个有效标签。初始提供 13 个**未启用**的建议标签，需由管理员核对后启用；没有可选标签时上传界面明确提示。旧文章无标签仍可阅读，不会自动贴词。

创建管理员：停止网站，运行 `manage-account.cmd`，选择创建管理员，自行输入账户和密码。重新启动后从右上角“管理”进入“标签”，核对并启用需要的词。可搜索、停用、调整顺序或合并标签；不允许普通用户随意创建词。不要将测试账户或测试词表复制到正式库。

## 升级现有数据

先记录当前源码版本及实际数据目录，然后正常停止网站。以下以 `D:\GAReaderData` 为示例，必须替换为自己的原数据目录；备份、安装、启动和账户管理始终指向同一目录。

```text
backup.cmd --data-dir "D:\GAReaderData"
setup.cmd --data-dir "D:\GAReaderData"
start.cmd --data-dir "D:\GAReaderData" --port 8047
manage-account.cmd --data-dir "D:\GAReaderData"
```

最后一条用于**停机时**管理账户，不要在网站运行期间执行。本次新增迁移建立标签及其关联、分类排序。重复 setup 会先备份，再应用缺失迁移、收集静态资源并初始化缺少的内容快照；不会重置账户、评分、评论或已有论文。

不要误用其他源码目录中默认的 `var/`；同一机器可能存在多个独立数据目录。`local.json` 中的实例标识用于草稿隔离，密钥用于登录会话，应保密保管。源码更新后浏览器刷新即可加载新静态资源。

本次本机执行已先备份两处原目录，并升级用户此前运行的实际目录。2 个原账户、2 篇论文及原文件核对保持；测试均在独立副本完成。原正式库没有管理员，因此未代建管理员、未替用户启用标签。可使用交付目录中的本机快捷启动／账户管理脚本，它们明确指向同一个原数据目录。

## 回退

1. 停止新版服务。如果升级后产生了新的正式数据，先用新版 `backup.cmd` 再备份一次，并保留现有目录。
2. 在另一源码目录准备升级前版本。此次基线为 `5afc70259bd2042f908346e52010a32c7b1dd7c0`，也可使用自己升级前保存的源码包。不要对含未提交修改的工作目录使用 reset/clean。
3. 用新版恢复工具将**升级前的备份**恢复到全新目录；工具拒绝覆盖已有目录。然后用旧版代码明确指定恢复目录运行 setup 和 start：

```text
restore.cmd --archive "D:\Backups\升级前备份.zip" --target "D:\GAReaderRollback"
```

```text
旧版目录\setup.cmd --data-dir "D:\GAReaderRollback"
旧版目录\start.cmd --data-dir "D:\GAReaderRollback" --port 8047
```

不要把新数据库直接交给旧代码，也不要手工倒退迁移或删除标签表。回退到升级前备份意味着新产生的记录仍只保留在第 1 步的新备份中；不得声称已经合并。旧备份恢复会生成新密钥，用户需重新登录，浏览器匿名身份记忆可能需要重新建立。

本轮已经实际执行隔离备份、独立恢复、逐行对比、旧修订回源及停止重启。回退时切换旧代码的正式操作未执行，因为当前正式站保留新版。备份含账户密码哈希，不能上传到公开仓库或放入源码 ZIP。

## 数据与阅读行为

评论、批注、评分、标签保存于服务器数据库；正文修订和 PDF 快照继续独立保存。修改题名、标签或分类不会改正文哈希、PDF 指纹、首次发布时间或批注源修订。未提交草稿和阅读偏好仍在浏览器本地，跨设备草稿同步没有新增。

关闭编辑器保留草稿，点击“丢弃”才删除。来源访问使用临时高亮，返回按钮恢复先前阅读上下文；“批注汇总”只在明确打开时出现。删除根评论后仍有可见回复的线程保留占位，没有可见内容的线程从计数与文中标记中移除。
